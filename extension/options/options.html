Providers

Choose the model the hub agent uses. Your API key is stored locally in chrome.storage — never in the bundle, logs, or receipts.

Tool library

Read-only diagnostics: the tools the platform can see, grouped by source. Nothing here runs, installs, grants, updates, or removes tools.

Agents

Multiple agents When off, the hub is a single agent. When on, the hub fans out to Site Agents.

Add a Site Agent

Grant access to one site so the tools it makes available can become Site Agent actions. Chrome requests only that site's origin — never broad <all_urls> access.

Site Agent diagnostics

Technical details for tool discovery on enrolled sites. Runtime lifecycle, tab setup, and page-reported tool counts stay here rather than in ordinary Site Agent rows.

Diagnostics logs Emit structured [WebMCP] logs from the discovery content scripts into the page DevTools console.

Per-agent providers

Each named agent can use its own provider + model (overriding the global). Its key is stored with the agent and never shown back here.

Background agents

Agents that run quietly on a schedule (each wraps a skill). Enable one to let it work in the background — e.g. the Sorting Hat groups your tabs by domain every 30 minutes.

Browser control

Open, navigate, and close tabs, and capture screenshots need your explicit, scoped permission. Reading page text and listing tabs are always available.

Allow the agent to control the browser Open, navigate, and close tabs, and capture screenshots.

Allowed origins

Empty = a global (all-origins) grant.

Permissions

Every permission is granted at install (this extension is loaded unpacked; it never ships to a store). This is the live, verified state of each grant — there is nothing to enable here. If any row shows MISSING, reload the extension.

Skills

Reusable capabilities, each documented below. A skill is included in a task — type /skill:name anywhere in the composer on the hub, or attach it to an agent. Use one here to start a task with it pre-filled.

System hooks

Every chrome.* event an agent can listen to + respond to. Deny a hook to stop the agent ever using it — the deny-list is authoritative and the agent cannot break past it. A hook's permission is granted at install; the deny-list is the control here.

Advanced — system prompts

The system prompt each agent runs with, layer by layer: the versioned built-in prompt, your customization, and the protected runtime policy (never editable, always applied last). The preview is the exact platform composition; every run also records a run-bound attestation of the exact provider-bound system message (digest + bytes, never content).

Data & memory

Per-origin memory is stored in OPFS, keyed by origin — one site can never read another. Browse each agent's memory below.

Agent data maintenance

Purge agent journals (the running activity logs — memory content and artifacts are kept), or clean up leftover files from agents that were removed before deletion cleaned up after itself.

Factory reset

Permanently delete all extension data — agents, tasks, artifacts, memory, alarms, downloaded models, provider settings, and permissions. Restores the clean first-run onboarding state.
